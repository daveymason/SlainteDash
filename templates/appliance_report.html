Deterministic 5-Step Ingestion Pipeline

A
Step A: Dropzone Scanning

Agent scans /workspace/data/raw/ for newly dropped unstructured CSVs, legacy records, or handwritten note scans.

[Agent] Scanning raw dropzone: /workspace/data/raw (found emergency_triage_batch_01.csv)
B
Step B: Deterministic MCP Schema & Terminology Discovery

Calls FastMCP tools to extract columns, resolve SNOMED-CT codes for chief complaints, and compute MTS acuity scores.

mcp.call("scan_clinical_schema", source="/data/raw/emergency_triage_batch_01.csv")
mcp.call("resolve_terminology", term_type="clinical", query="Crushing chest pain") -> SCTID: 29857009
mcp.call("calculate_mts_category", vitals={"systolic_bp": 82, "spo2": 87, "heart_rate": 148, "pain": 9}) -> Cat 1
C
Step C: Irish Core FHIR R4 Compilation

Builds structured FHIR R4 Bundle with Patient (Irish OID urn:oid:1.3.6.1.4.1.54392.5.2690.42.80), Emergency Encounter, Condition, and LOINC Observations.

D
Step D: Zero-Hallucination MCP Validation Gate (Mandatory)

Validates compiled JSON against official FHIR R4 schema and semantic rules. Rejects unvalidated or hallucinated resources.

mcp.call("validate_fhir_resource", resource=bundle) -> {"valid": true, "errors": [], "resource_count": 11}
E
Step E: Atomic Persisted Storage & Immediate Dashboard Indexing

Atomically persists validated bundle to /workspace/data/fhir_store/bundle_{patient_id}.json. HTMX interface instantly detects and updates queue.
